Signals drive the mixer, one AudioPool sits under each bus, and plays made before the browser unlocks audio are not dropped - they queue and fire on the first gesture. This demo drives the engine's unlock through an injected window, so the part you normally only get one shot at is replayable.

The engine listens for touchstart / touchend / mousedown / keydown at capture phase, pulses a silent buffer (iOS needs it), calls resume(), and flushes the queue. Real clicks would unlock it instantly, so this demo hands the engine a fake window via opts.window and fires the gesture itself.

Assets are synthesized in an OfflineAudioContext, encoded to WAV, and handed to the engine as blob: URLs - so the demo is one file with no asset folder, and still exercises the real fetch + decode path. thunder is served through an injected fetch with 2.6s of artificial latency; broken is answered with a 404 by that same injected fetch, which walks the loader's real error path without a real request failing in your console.

A play aimed at a sound that has not landed yet returns -1 and joins the same queue: defineSounds() flushes it the moment the buffer decodes. Press reload, then play thunder immediately - it fires 2.6s later, on its own.

Every write lands as setTargetAtTime(target, now, 0.01), never a raw .value =. Mute a bus mid-tone and watch the trace bend instead of stepping - that bend is the click you do not hear. Master mute survives a reload: it is persisted under the same localStorage key lite-audio-manager used, on purpose.

the twin-handle trap

Every pool counts channels and generations from zero, so the first play on sfx and the first play on ui both come back as raw pool handle 0x00000000. Press issue twin handles to see it.

The engine tags the bus above the pool's 32 bits: busIndex * 2^32 + poolHandle. The raw column is what the pool returned; the bus column is what makes the handle name one voice engine-wide. Without the tag, stop() on an sfx handle would also kill whatever sat on channel 0 of every other bus.
